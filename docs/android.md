# Personal AI for Android

## Status and architecture

The Android project lives in `android/`. It is a small native Java Android WebView shell for the existing server-rendered Next.js assistant. Capacitor is not used: this app depends on Next.js server/API routes and cannot be deployed as a self-contained static Capacitor export without redesigning the backend and authentication. The native shell provides a first-run HTTPS server configuration, navigation, file picker, microphone permission mediation, and connection-error screen; the web application continues to provide chat, history, uploads, account and theme controls.

**Important:** there is currently no assistant backend URL bundled or verified in this repository. On first use, select **Set server** and enter the HTTPS origin of a deployment you control, for example `https://assistant.example` (no path or credentials). The app will not provide chat until that server is deployed and its AI provider is configured. The URL is a public address, not an API key. It is stored in Android app-private preferences. A preview URL may expire and is not a production backend. No Vercel project, account, provider key, or paid service is created by this project.

The application ID is `com.khaurfield.personalassistant` (change it before publishing if you need a different identifier). It targets Android API 35, with minimum API 26. Galaxy A07 compatibility still requires a physical-device test; an APK build alone does not verify device behavior.

## Security and privacy

- Only HTTPS origins without embedded credentials, paths, queries or fragments are accepted. Main-frame navigation stays on that exact origin; other HTTP(S) links open in the system browser. Cleartext and mixed-content requests are disabled. Never enter an untrusted server: it receives anything you type or upload.
- No AI/API key, signing key, or password is packaged in the APK. AI keys and authentication secrets belong in server-side environment variables, not the app, source, URL, or `NEXT_PUBLIC_*` values. A debug signing key is automatically generated by Android tooling and is **not** a release key.
- Sessions use the existing server-issued `HttpOnly` cookie in the WebView cookie store, not a JavaScript token or native preferences. HTTPS and a correctly configured production backend are required for the server's `Secure` cookie. Third-party cookies and Android backup are disabled. WebView data is app-private, but this project does **not** claim cookies or conversation history are encrypted at rest; lock the phone, sign out on shared devices, and check the web app's retention settings. Changing server does not automatically delete the old server's cookies; sign out there first if needed.
- Images and documents use Android's system document picker; there is no camera permission. The chosen file is sent only as part of the user's upload action to the configured web app. The backend validates supported types and limits.
- Microphone access requires an explicit web microphone request **and** Android runtime consent, and is granted only to the configured HTTPS origin. Other requested WebView resources, including camera capture, are denied. Android WebView speech-recognition and microphone behavior vary by device; physical testing is required.
- The native app has no JavaScript/native plugin bridge. External links open outside the app. TLS failures are not bypassed. The selected backend, its web content, model provider and third-party dependencies must still be trusted; these controls cannot prevent all attacks.

## Debug build and artifact

The **Android debug APK** GitHub Actions workflow runs `testDebugUnitTest` and `assembleDebug`, checks the package ID, verifies the debug signature with `apksigner`, checks alignment, and uploads `personal-ai-android-debug` containing `app-debug.apk` and `SHA256SUMS.txt`. The [verified build run 42627197511](https://github.com/khaurfield/premium-web-starter/actions/runs/42627197511) succeeded for commit `565b198`; [artifact 13678399408](https://github.com/khaurfield/premium-web-starter/actions/runs/42627197511/artifacts/13678399408) expires on 2026-12-09 at 13:38:58 UTC. GitHub authentication may be required to download it. A debug APK is signed with the runner's debug key, so a later debug build might not install as an update over it without uninstalling the old one. Uninstalling clears local history and app data.

For a local build (Android Studio or command line), install JDK 17, Android SDK platform 35 and build-tools 35.0.0, then:

```sh
cd android
./gradlew testDebugUnitTest assembleDebug
# android/app/build/outputs/apk/debug/app-debug.apk
```

The `android/` path in the comment is relative to the repository root; while already in `android/`, use `app/build/outputs/apk/debug/app-debug.apk`. The Gradle wrapper distribution and wrapper JAR are pinned with SHA-256 checksums. No local Android SDK or connected Android device was available during initial implementation; use the actual workflow result as the source of truth for whether an APK has been built and verified.

## Install and test on your Samsung Galaxy A07

1. From a **successful** GitHub Actions run, download the `personal-ai-android-debug` artifact ZIP, extract `app-debug.apk`, and compare its SHA-256 against `SHA256SUMS.txt` when possible.
2. Transfer it to your phone. Open it from Files and, when prompted, allow **Install unknown apps** for the specific app used to open the APK. Revoke that permission afterward if you do not need it.
3. Open Personal AI, select **Set server**, and enter your deployed backend's HTTPS origin. Confirm you control and trust the server before signing in. Configure the AI provider and persistent storage on that server, not on the phone.
4. Test chat and streaming, restart the app and inspect history, sign in and restart to check session persistence, try image and document selection, exercise microphone allow/deny, switch light/dark themes in the web app, and test airplane mode and Retry. Server-side account history requires a configured persistent database; process-local storage is not durable.
5. The Android document picker and microphone are platform-dependent. If a test fails, record the Android version, WebView version, screen, and error; do not include passwords, tokens, private document contents, or screenshots containing sensitive data.

If installation is blocked by a conflicting signature, uninstall the earlier app first **only after exporting anything you want to keep**. A successful workflow verifies APK structure and signature, not actual installation, device compatibility, backend health, live AI responses, or security guarantees.

## Signed release preparation

The separate **Android signed release** workflow is manual (`workflow_dispatch`) and produces a signed APK and AAB artifact, not a GitHub release or Play Store publication. GitHub requires a `workflow_dispatch` workflow to exist on the repository's default branch before it can be invoked from the UI; after that select a trusted ref. Set these GitHub Actions **secrets** before running it:

- `ANDROID_KEYSTORE_BASE64`: base64 of the private release keystore.
- `ANDROID_KEYSTORE_PASSWORD`
- `ANDROID_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

Generate and back up the keystore securely outside this repository. Never commit it or paste secrets into chat. The workflow decodes it into the runner's temporary directory, uses it for signing, and removes it after the step. Download and independently verify the APK certificate fingerprint against your own recorded release-key fingerprint before distributing. Protect the key: losing it may prevent future updates; compromising it allows malicious updates. Release signing has not been run unless a successful signed-release workflow is explicitly identified.
